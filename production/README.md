# AI Staff 채널 제작 엔진 v1.1

AI Staff의 목적은 직원 캐릭터를 여러 홍보 채널에 맞게 활용하는 것이다. 블로그 제작은 하나의 하위 어댑터다. 공통 브리프의 메시지·근거·캐릭터 기준을 공유하고, 각 채널의 길이·전개·화면 비율에 맞는 별도 작업을 만든다.

저장소 루트에서 `node blog/server.cjs` 실행 후 출력된 주소의 **/production/**을 연다. 서버·보관함은 블로그 어댑터와 공유한다. 기본 보관함은 `D:/dev-artifacts/ai-staff/blog-engine-20261114/library`다. 로컬 실행용이며 운영 배포·계정 연결·자동 발행은 하지 않는다.

## 공통 흐름

1. 주제, 대상, 핵심 메시지, 기대 행동, 선택적인 출처 메모를 작성하고 제작할 채널을 고른다.
2. 공통 캠페인의 ID와 SHA256를 만들고 채널별 작업지시를 생성한다. 무료 GPT를 포함한 텍스트 모델에 지시문 TXT를 전달한다. 이 도구 자체에는 유료 API 호출이 없다.
3. 채널에 맞게 완성한 JSON을 가져온다. 고정된 채널 스키마, 캠페인 결합, 근거 ID, 예정 시간, 문구 길이, 같은 채널의 로컬 대본 중복을 검사한다. 예시 문장이 남은 원고는 거절한다.
4. 채널별 크기의 PNG를 만든 뒤 원고·이미지·검수 결과·manifest·SHA256가 든 ZIP을 내려받는다. 기존 채널 담당이 내용과 실제 게시 결과를 확인한다. PC1 자동 파일 전송은 구현하지 않았다.

| 채널 | 현재 출력 | 내부 제작 이미지 프리셋 |
|---|---|---|
| 블로그 | 6종 편집 구성, 본문, 표지·정보 PNG, 네이버 분할 HTML/CF_HTML/AI Link manifest | 표지1200×900, 본문1200px·내용별높이 |
| 유튜브 일반 | 대본, 장면표CSV, 예정SRT, 업로드 문구, 썸네일·장면 PNG | 1280×720 |
| 유튜브 쇼츠 | 15~60초 예정 대본·세로 장면표, 예정SRT, 업로드 문구, 커버·장면 PNG | 1080×1920 |
| 홈페이지 홍보 | 영역별 카피, 이미지 설명, 배너·영역 PNG | 1600×900 |
| 카드뉴스·SNS | 카드별 문구, 게시 문구, 표지·연속 PNG | 1080×1350 |

위 크기는 이 엔진의 제작 프리셋이며 플랫폼의 강제 업로드 요건이라는 뜻은 아니다. 홈페이지 출력은 범용 홍보 자료이며 실제 홈페이지의 특정 영역에 적용·배포하거나 계산기 기능과 연결하지 않는다. 실제 슬롯의 크롭과 UI 겹침은 별도로 검수해야 한다.

영상 채널 ZIP은 **제작 자료**다. 영상 렌더링·실제 음성 합성·립싱크는 아직 수행하지 않는다. 기존 A1 승인 음성은 참조 자산이며 새 대본을 읽은 것처럼 붙이지 않는다. SRT는 대본과 예정 장면 시간으로 만든 편집 계획이므로 실제 녹음·편집 뒤 타이밍을 다시 맞춰야 한다. manifest는 copy/images/audio/video/subtitles 상태를 구분하며 미제작 파일이 존재하는 것처럼 기록하지 않는다.

## 직원·브랜드와 검수

현재 시각 렌더러의 승인된 자산은 **CLO-02 착한 클로이 Ver.2.0** 6포즈다. 기존 로봇 정본의 번호·이름은 robots/registry.json을 따른다. 착한거래 파생 자산 세트 참조를 공통 character_ref에 고정하며 다른 직원 정본·사람형 보류 상태·업무 owner를 변경하지 않는다. 다른 직원이 추가되면 승인된 자산 매핑과 각 렌더러의 지원 여부부터 등록해야 한다.

직원의 정본 자산, 브랜드 서체·색상, 공통 메시지·근거는 중앙 기준이다. 채널별 어댑터는 출력 계약만 담당한다. 같은 대본을 모든 채널에 복사하지 않는다. 브리프를 바꾸려면 새 캠페인을 만들고 새 hash로 제작한다. 과거 산출물을 새 캠페인 ZIP에 섞지 않는다.

해시 일치는 기준 버전 결합만 확인한다. 주장 의미·가격·약관의 사실성은 자동 검증하지 않는다. 출처 메모와 fact_ids 연결을 검사하되 content_review는 required다. 외부 유튜브/SNS/홈페이지 게시 목록은 아직 연결하지 않았으므로 그 채널들의 중복 상태는 duplicate_unknown이다. 블로그 RSS 결과를 다른 채널의 게시 이력으로 사용하지 않는다. 발행 승인은 모든 묶음에서 false다.

시연 체크로 만든 캠페인은 manifest에서 demo_only로 표시한다. 화면의 시연 캠페인과 원고는 사용법 확인용이다. 실제 발행 원고로 취급하지 않는다.

## 확장 위치와 검증

`core.js`의 CHANNELS·채널별 검사·promptFor·packageFiles가 어댑터 경계다. `renderer.js`는 승인 자산을 사용한 코드 기반 PNG 렌더러다. `../blog/`는 블로그 전용 어댑터이며 공통 캠페인 ID/hash를 그대로 가져간다. 새 채널은 전용 규격·출력·검증을 등록하고, 영상·음성 후속 도구는 기존 manifest의 제작 상태를 실제 파일 검증 후 갱신하는 별도 단계로 붙인다.

`node --test production/core.test.cjs blog/core.test.cjs blog/server.test.cjs`로 계약·저장 시험을 실행한다. `node production/verify-browser.cjs`는 이 PC의 기존 Playwright/Edge로 시연 캠페인 생성,4채널 가져오기·PNG·ZIP 다운로드, 블로그 주문 결합, 모바일390px 가로넘침을 확인한다. 검증 스크립트의 로컬 런타임 경로는 다른 PC에서 조정해야 한다. 이미지 원본은 git에 넣지 않고 기존 D:/large 자산을 읽는다.
